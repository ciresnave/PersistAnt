---
`persistant_kv::text_conformance::certify(target, backend, version, config, env)` (feature `text-index`) records `text.index` for a kv backend: **on** only when the target passed and both controls behaved, **off as missing** where the backend says `Unsupported`, **off as wrong** where an operation answered otherwise. The checks run `TextIndex` against a plain map after every operation of a 30-step scripted sequence of puts, replaces and removals (totals, every document's length, every term's postings paged by two, the document list, Any and All searches, and the exact count of posting keys, so a stale posting is caught), then eight concurrent writers of different documents (totals exact) and of one document with eight texts (exactly one survives), five rounds each. The concurrent writers run on one task with a yield before every read and batch, so every writer reads before any writes: that is what makes a batch that ignores its `Require` visible. Controls: a correct memory kv passes; memory kvs whose batch ignores its `Require` or is not applied as a unit must fail (they do).

Rows: **on** for `sqlite`, `sqlite-full`, PostgreSQL, MySQL and MariaDB (`kv-on-relational:*`; the PostgreSQL, MySQL and MariaDB rows are written by hand to the generator's format and checked by the CI matrix diff against the real servers); **off, missing** for the four `KvOnBlob` configurations on OpenDAL (no `ordered_scan_values`). `text.index` is in the vocabulary. The `checked_in_matrix_*` counts move accordingly (+1 per server file, +2 for SQLite). Not yet: the tokenising helper (`text-index-tokenizer`) and erased removal.
