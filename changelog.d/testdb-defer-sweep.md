kind: feat: `TestDb` can skip its per-test drop (`Cleanup::Defer`) and `TestDb::sweep` clears old test databases in one pass
---
`DROP DATABASE .. WITH (FORCE)` forces a checkpoint, so many `TestDb` drops at once queue behind it (Humboldt, ROADMAP row 36: 19 tests, 70 s with the drop against 15.7 s without; I did not repeat that measurement). `TestDb::create_with(&admin, TestDbOptions::default().cleanup(Cleanup::Defer))`, or `PERSISTANT_TESTDB_CLEANUP=defer` in the environment of `TestDb::create`, leaves the database when the handle goes out of scope; `TestDb::sweep(&admin, older_than)` drops, one at a time, every database named by this module (`persistant_test_<digits>_<digits>_<digits>`, the middle number being the creation time) that is older than the bound, and returns how many. Run it once at the start of the test binary or CI job with a bound longer than any test: a bound of zero also drops a parallel binary's live databases. Nothing else is touched: a database someone named `persistant_test_x` is left alone. `drop_database` still always drops, and the default mode is unchanged. Verified against PostgreSQL 16 by `tests/test_db.rs`: Defer leaves the database and the default drops it (control), an explicit `drop_database` drops a deferred one, and `sweep` drops an old name while keeping a younger one and two look-alike names; unit tests cover the name parser and the environment value. Additive.
